# M2 → M3 Interface Contract

**Owner:** Shaswat / M3  
**Consumer:** Suhan / M2  
**Model:** `sentinel_model_v3_stratified_candidate.pkl`  
**Schema version:** v3  
**Window size:** one second  
**History length:** five previous windows

## 1. Required live flow

M2 may capture raw packets using Scapy, but M3 must receive the packets after conversion through the shared pipeline:

```text
M2 raw capture
→ ml/feature_pipeline_v2.py
→ window_features(...)
→ RollingFeatureState.enrich(...)
→ one complete 45-feature window
→ m3-ml-ledger/src/predict_v3.py
```

M2 must not create a second feature extractor and must not send the legacy five-feature vector to M3.

## 3. Window metadata

The feature pipeline may also return metadata fields:

```text
timestamp
window_start_epoch
source_file
label
```

Metadata is not part of the 45-feature model vector. M3 selects only the 45 model columns before calling `predict_proba()`. `label` is for offline datasets and validation only; it is not available from ordinary live traffic.

Each live window should represent approximately one second of traffic. Empty windows should still produce a valid zero-valued feature row when the live capture policy chooses to include them.

## 4. M3 input call

The integrated predictor accepts a complete feature window:

```python
from ml.feature_pipeline_v2 import capture_live_window
from predict_v3 import AnomalyScorer

scorer = AnomalyScorer(organization_id="stable_organization_id")
scorer.start_calibration()

feature_row = capture_live_window(
    timeout=1.0,
    iface="br0",
    history_state=scorer.history_state,
)
result = scorer.ingest_feature_window(feature_row)
```

The old method `ingest_features()` must not be used. It intentionally raises an error because the legacy five-feature input is incompatible with v3.

## 5. Organization-ID rules

The organization ID identifies the server or organization whose normal traffic profile is being learned. It must remain stable across restarts and must not change randomly between runs.

The v3 scorer follows this priority:

1. An explicit `AnomalyScorer(organization_id="...")` constructor argument.
2. The `SENTINEL_ORGANIZATION_ID` environment variable.
3. `default_organization` if neither is supplied.

The ID is sanitized for filenames. For example, `North Office / Server 1` becomes `North_Office___Server_1`.

Profiles and state are stored separately per organization:

```text
ml/adaptive_profiles/<organization_id>_profile.json
ml/adaptive_profiles/<organization_id>_state.json
```

For deployments that need a different storage root, use:

```text
SENTINEL_PROFILE_ROOT
SENTINEL_STATE_ROOT
```

The profile and state must never be shared between two organizations. The scorer checks that the persisted profile organization ID and feature schema match the requested organization.

## 6. M3 result contract

`AnomalyScorer.ingest_feature_window()` returns a dictionary with these fields:

| Field | Type | Meaning |
|---|---|---|
| `state` | string | `calibrating`, `armed`, `alert`, or `lockdown` |
| `score` | float | Combined score used by the current pipeline |
| `probability_attack` | float | v3 Random Forest attack probability |
| `threshold` | float | Selected v3 threshold; currently 0.55 |
| `is_anomaly` | boolean | Current combined alert decision |
| `global_prediction` | string | `ATTACK` or `BENIGN` from the frozen v3 model |
| `local_prediction` | string | `ANOMALY`, `NORMAL`, or `LEARNING` from the local profile |
| `local_detection_enabled` | boolean | Whether the baseline time and profile readiness gates are complete |
| `organization_id` | string | Sanitized stable organization identifier |
| `profile_ready` | boolean | Whether the minimum accepted baseline is complete |
| `profile_samples` | integer | Number of accepted windows in the local profile |
| `eligible_for_learning` | boolean | Whether this window was accepted as likely normal for profile learning |
| `local_score` | float | Local adaptive anomaly score |
| `top_local_features` | list[string] | Features contributing most to the local diagnostic score |
| `feature_count` | integer | Must be 45 |
| `timestamp` | string | Window timestamp or generated UTC timestamp |

M2 should pass the complete result object onward rather than reconstructing a second interpretation of the ML decision.

## 7. Learning behavior

During the initial baseline period, the frozen v3 model remains unchanged. The local profile accepts only windows that pass the learning gate: the global attack probability is at or below the configured benign-acceptance limit and the local profile does not already call the window anomalous.

Local alerts remain disabled until both conditions are true:

```text
baseline time is complete
AND
minimum accepted profile samples are available
```

The default baseline duration is 172,800 seconds (48 hours), and the default minimum profile size is 2,048 accepted windows. These values can be configured with environment variables, but changes must be documented for each deployment.

## 9. Current ownership boundary

M2 owns packet capture, interface selection, bridge/OS operation, and delivery of packets or feature windows. M3 owns the shared feature definition, model loading, adaptive profile, scoring result, ledger evidence, and M3 validation. M2 does not need to implement relay logic, hardware key destruction, or ML retraining.
